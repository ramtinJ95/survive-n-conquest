# survive-n-conquest verification map

This directory is the maintained source for verifying what a player sees and does in survive-n-conquest. Read this index before you drive the game, then use the matching feature file as the recipe.

## Baseline preconditions

- The checkout under test has run `bun install`, and its working tree holds the change you are proving.
- Headless Chromium and Playwright's ffmpeg are installed, and `ffmpeg` and `bun` are on `PATH`. In a Nexus pylon, `.nexus/setup` installs them.
- The game runs from a production build that `verify.mjs launch` or `verify.mjs run` started on a free port.
- `verify.mjs doctor` passes every check.
- Never drive an instance that this verification run did not start.

## Driving conventions

- Run every command from the checkout root, with `V=.claude/skills/verify-survive-n-conquest/scripts/verify.mjs`.
- Each feature has one scenario in the `SCENARIOS` table of `verify.mjs`. The scenario name matches the feature file name.
- Locate the world by `canvas#world`. Locate interface elements by ARIA role and accessible name once they exist.
- Drive through the page only: viewport size, pointer, and keyboard.
- Start every scenario from a fresh page load. The game keeps no saved state yet.
- Choose the map with the `seed` URL parameter, through `open(viewport, { search: '?seed=7' })`.
- The game opens with 8 settlers at the camp. `swarm=on` opens it with 1500 villagers and 3000 monsters, and `swarm=off` with no units. Units hold still while the clock is paused, so screenshots from one paused page compare cleanly. Every page opens paused at tick 0, and `reach` stops on the first tick of its minute, so two page loads stopped at the same minute stand on the same tick and show the same units in the same places.
- Each scenario opens the game the way its checks need. `window` and `clock`, and the clip of `camera`, open with the settlers. `terrain`, `seasons`, and the checks of `camera` open with `swarm=off`. `swarm` and `daylight` open with `swarm=on`, because their checks count villager and monster pixels. `settlers`, `gathering`, and `hauling` open with the settlers, and compare them with `swarm=off`. `building` opens both its pages with the settlers, because they supply and build the house. `look` opens with the settlers for the same reason, and its last page with `swarm=on`. `households` opens its first page with the settlers, who build two houses, and compares it with a page of settlers and no orders and a page with `swarm=off`. `selecting` opens every page with the settlers, because it selects them, their work, and their house. `hunger` opens with the settlers on seed 7 and gives no orders. `aging` opens with the settlers on seed 7, and its last page with the `settlers` setting. `births` opens every page on seed 7 with the `settlers` setting, every page but the player's with `firewood-year`'s orders, and its fed pages with `?food=200`. `firewood-reason` and `clothing-reason` open on `?seed=7` with no `food` setting and give #40's years through the toolbar. `growing-up` opens the same way with `?food=200` and four children of 9. `pairing` opens its pages on seed 7 with the `settlers` setting, its pages with houses with `firewood-year`'s orders and `?food=200`. `people` opens the `births` page with one household more at the camp and `?food=200`. `empty-house` opens on seed 7 with the `settlers` setting, `firewood-year`'s orders, and the camp's own food. `eating` opens with the settlers on `?seed=7&food=0`, so the settlers miss the meal of the first dusk and the camp gets its food from the foragers by day. `foraging` opens with the settlers on seed 7 and no `food` setting, because the food its foragers bring in is what it proves. `storing` opens its first page the same way, and its ground page with `?seed=7&food=8`, so the camp never fills and the foragers keep picking. `hunting` opens with the settlers on seed 7, no `food` setting, and no hut, so every unit that enters a store on day 2 comes from a kill. `firewood` opens with the settlers on seed 7 and no `food` setting, because it ends before the first dusk, when the settlers first eat. `clothing` opens with the settlers on seed 7 and no `food` setting. `sowing` opens with the settlers on seed 7 and no `food` setting, because the camp's 24 food last the four days it plays. `harvest` opens with the settlers on `?seed=7&food=56`, because the camp's food must last to the harvest of day 6. `frost` opens with the settlers on `?seed=7&food=100`, because the camp's food must feed them until the harvest comes into the barn, and its two warm houses keep two households alive to sow in the next spring. `cold`, `wearing`, and `readiness` open with the settlers on seed 7. `look`, `selecting`, `cold`, `wearing`, and the first page of `readiness` open their pages that run to winter with `?food=200`, because the 24 food of a new game run out and the settlers die at the dusk of day 6. The page of `orders` that runs the clock opens with `swarm=off`, because the settlers would work its marks.
- Wait with `still(page)` before every screenshot. The camera eases into place.
- Pin the time before you compare screenshots, because the light and the colors of the map follow the clock. `open` runs every page to 12:00 on day 1 and pauses it there unless you pass another `clock`. `reach(page, { day, time })` pins any other time, on the first tick of that minute.
- Give the orders on a paused page, right after `open` at 08:00 or at a `reach` stop, so they land on the same tick on every run. Wait for something to happen with `runUntil` or `labelGone`, which step the paused clock, never with a loop that polls a running clock. Take every check from a paused stop.
- A check that reads the colors of the land opens the page with `swarm=off`. Villager yellow reads as an autumn leaf, and monster red over snow reads as blossom.

## Proof and skip reporting

- Capture the user action and the resulting state. Each scenario records a GIF clip of the action and screenshots of the states before and after it.
- Pair each screenshot with the pixel or layout checks from `result.json` that cover it.
- Record the build revision from `result.json` with every artifact. A revision that ends in `-dirty-<hash>` was built from uncommitted changes, and the hash names those changes.
- Report a scenario that cannot run with the command and the failing doctor check.
- Do not report a feature as verified through a different scenario.

## Feature entry contract

Each feature file starts with an H1 title and one paragraph describing the player-visible behavior. It then uses exactly four H2 sections in this order.

1. `Sub-features` lists short IDs with one line for each behavior.
2. `How to get to it (user POV)` lists every player entry point.
3. `Driving it with verify.mjs` starts with `Preconditions:` and uses labeled bullets that pair each player action with the scenario step and the observable result.
4. `Gotchas` lists traps that can waste or invalidate a verification run.
